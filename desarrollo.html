Semana 07 / 17
Prototipo de Movimiento del Jugador
Fecha: Marzo 2026
✓ Completado
🚀 Descripción del Avance

Durante esta semana se trabajó en la base jugable del personaje principal, enfocándonos en la implementación del script de movimiento del jugador. El objetivo era establecer una movilidad inicial sólida que sirviera como punto de partida para futuras mecánicas de combate, desplazamiento y pruebas dentro del entorno de juego.

🎯 Objetivos Alcanzados
✓
Se implementó el script de movimiento del jugador
✓
Se ajustó la movilidad base del personaje
✓
Se dejó preparada una estructura inicial para conectar luego el combate y otras mecánicas
✓
Se realizaron pruebas básicas de control dentro del escenario
⚠️ Complicaciones

Uno de los principales retos fue lograr que el movimiento no solo funcionara técnicamente, sino que también se sintiera fluido y cómodo al jugar. Fue necesario hacer varias pruebas para encontrar un balance entre control, respuesta y naturalidad.

🔗 Coherencia con la Propuesta

Este avance se relaciona directamente con la propuesta del juego, ya que desde el documento se plantea una experiencia de combate en primera persona con movilidad activa y un enfoque en ejecución mecánica. Por eso, definir primero el desplazamiento del jugador era una base necesaria antes de implementar sistemas más complejos.

🔜 Próximos Pasos

Comenzar la implementación del enemigo base y preparar un entorno de prueba donde se puedan validar interacciones reales entre jugador y enemigo.

Semana 08 / 17
Programación Base del Enemigo
Fecha: Marzo 2026
✓ Completado
🤖 Descripción del Avance

En esta semana se avanzó en el desarrollo técnico del enemigo, centrándonos en el funcionamiento del script enemigo y en su programación general dentro de la escena. La intención fue dejar una primera versión funcional que permitiera comenzar a probar comportamientos básicos.

🎯 Objetivos Alcanzados
✓
Se desarrolló el script base del enemigo
✓
Se programó su comportamiento inicial
✓
Se validó su funcionamiento dentro del escenario de prueba
✓
Se dejó lista una base para futuras ampliaciones, como ataques y estados
⚠️ Complicaciones

La dificultad principal no estuvo solo en hacer que el enemigo apareciera o se moviera, sino en organizar su lógica de forma que más adelante permitiera crecer el sistema sin tener que rehacerlo por completo.

🔗 Coherencia con la Propuesta

En la propuesta se define un sistema de avance basado en oleadas de enemigos, jefes y patrones de combate diferenciados, así que este paso era fundamental para pasar del planteamiento conceptual a una implementación real dentro del motor.

🔜 Próximos Pasos

Agregar las primeras acciones ofensivas del enemigo y comenzar a probar interacciones de combate más claras.

Semana 09 / 17
Primeras Mecánicas de Ataque del Enemigo
Fecha: Marzo 2026
✓ Completado
⚔️ Descripción del Avance

Durante esta semana se implementaron las primeras acciones ofensivas del enemigo con el fin de construir una base de combate más dinámica. Se desarrollaron tres scripts de ataque que permiten empezar a diferenciar comportamientos y generar variedad en los enfrentamientos.

🎯 Objetivos Alcanzados
✓
Se creó el script de ataque horizontal
✓
Se creó el script de ataque vertical
✓
Se creó el script de lanzamiento de hacha
✓
Se hicieron pruebas iniciales entre ataques cercanos y ataques a distancia
✓
Se avanzó en una base de combate más variada
⚠️ Complicaciones

El reto principal fue conseguir que cada ataque se sintiera distinto y tuviera una función clara dentro del combate. No se trataba solamente de programar tres acciones diferentes, sino de empezar a construir un sistema con lógica y posibilidades de expansión.

🔗 Coherencia con la Propuesta

Este avance tiene mucho sentido dentro del documento, especialmente porque uno de los personajes planteados, El Verdugo, ya estaba definido con ataques telegráficos y lanzamiento de hacha. Además, la propuesta general del juego gira alrededor de combates técnicos, agresivos y con lectura de patrones.

🔜 Próximos Pasos

Probar estos ataques en un entorno más controlado y empezar a trabajar en sistemas complementarios que afecten al enemigo durante el combate.

Semana 10 / 17
Sistema de Pruebas y Efectos de Estado del Enemigo
Fecha: Marzo 2026
✓ Completado
🧪 Descripción del Avance

En esta fase se construyó un campo de pruebas para validar de manera más ordenada los sistemas ya desarrollados. Además, se avanzó en uno de los componentes técnicos más importantes hasta el momento: permitir que el enemigo almacenara efectos de estado, como envenenamiento y corrosión.

🎯 Objetivos Alcanzados
✓
Se creó un campo de pruebas para testear mecánicas
✓
Se implementó un sistema para almacenar efectos de estado en el enemigo
✓
Se realizaron pruebas con estados como envenenamiento y corrosión
✓
Se organizó mejor la lógica del enemigo para soportar nuevas interacciones
⚠️ Complicaciones

Esta fue una de las partes más complejas del proceso, porque requería que el enemigo pudiera guardar, actualizar y mantener varios efectos sin que la lógica se volviera desordenada. Fue un trabajo más estructural que visual, pero muy importante para el avance técnico del proyecto.

🔗 Coherencia con la Propuesta

Dentro de la propuesta ya se contemplaban sistemas relacionados con veneno, corrosión, reducción de armadura y distintas interacciones entre perks, hazards y enemigos. Por eso, desarrollar esta lógica no solo aporta al prototipo actual, sino que también deja preparada la base para futuras mecánicas estratégicas del juego.

🔜 Próximos Pasos

Conectar estos efectos con armas, ataques y futuras interacciones del sistema de combate.

Semana 11 / 17
Integración Visual del Prototipo y Armas Cuerpo a Cuerpo
Fecha: Marzo 2026
✓ Completado
🎨 Descripción del Avance

Durante esta semana se trabajó en la integración entre la parte técnica y la parte visual del proyecto. Se avanzó tanto en el sistema de armas cuerpo a cuerpo como en varios modelos esenciales del juego, permitiendo que el prototipo empezara a verse más cercano a una versión temprana del producto final.

🎯 Objetivos Alcanzados
✓
Se implementó el script de las armas cuerpo a cuerpo
✓
Se realizó el modelo de las armas cuerpo a cuerpo
✓
Se hicieron los modelos del enemigo y del hacha
✓
Se avanzó en el modelo del personaje principal y de los jefes
✓
Se integraron mejor los componentes jugables con la identidad visual del proyecto
⚠️ Complicaciones

La parte visual presentó varias dificultades, especialmente en modelado. Más allá de lo técnico, fue necesario tomar decisiones creativas para que los diseños mantuvieran coherencia con la estética general del juego y no se sintieran desconectados del tono planteado.

🔗 Coherencia con la Propuesta

Este avance se alinea directamente con el documento, donde se define una estética 3D low poly con texturas pintadas a mano, así como personajes y jefes con una fuerte carga visual. También encaja con la importancia de las armas, los jefes y el protagonista dentro de la identidad del proyecto.

🔜 Próximos Pasos

Continuar integrando sistemas jugables con los elementos visuales, mejorar la sensación del combate y seguir consolidando el prototipo general.
