05 / 17 — Conceptualización

Conceptualización y Propuesta

Marzo 2026
Completado
Descripción del Avance

Definición del concepto central: un roguelike FPS ambientado en la mente de un joven en coma, con las etapas del duelo como estructura narrativa y ludológica.

Desarrollo de la premisa, el perfil de usuario objetivo y la clasificación ESRB. Análisis inicial de la competencia con referencias en Ultrakill, Doom y Balatro.

Objetivos Alcanzados
✓
Concepto y título definidos: Fallen Souls
✓
Género confirmado: FPS Roguelike + Action RPG
✓
Plataformas objetivo seleccionadas (PC, PS5, XSX, Switch)
✓
Perfil de usuario creado
✓
Clasificación ESRB: Mature 17+ justificada
✓
Documento de propuesta entregado
Complicaciones

Definir el balance entre narrativa simbólica y jugabilidad roguelike fue el mayor desafío conceptual. Se optó por integrar ambas dimensiones sin sacrificar ninguna.

La metáfora psicológica debía mantenerse coherente sin volverse didáctica ni forzada. Decisión: los elementos narrativos emergen del diseño de niveles, no del diálogo.

Próximos Pasos
Profundizar diseño de personajes
Definir mecánicas core del combate
Establecer sistema de progresión roguelike

Semana 07
07 / 17 — Programación

Prototipo de Movimiento del Jugador

Marzo 2026
Completado
Descripción del Avance

Implementación del script base de movimiento del jugador. El objetivo fue establecer una movilidad inicial sólida que sirva como fundamento para las mecánicas de combate y desplazamiento.

Se priorizó la fluidez y la respuesta del control antes de añadir capas de complejidad mecánica.

Objetivos Alcanzados
✓
Script de movimiento del jugador implementado
✓
Movilidad base ajustada y refinada
✓
Estructura lista para integrar combate y mecánicas futuras
✓
Pruebas básicas de control dentro del escenario
Complicaciones

El reto principal no fue el funcionamiento técnico sino la sensación. El movimiento debía sentirse fluido y natural, no solo funcionar en papel. Múltiples iteraciones de valores de velocidad, aceleración y fricción.

Coherencia con la Propuesta

La propuesta plantea un FPS de alta movilidad con dash y reposicionamiento activo. Establecer el movimiento base antes que cualquier otro sistema fue una decisión arquitectural deliberada.

08 / 17 — Programación

Programación Base del Enemigo

Marzo 2026
Completado
Descripción del Avance

Desarrollo del script base del enemigo con enfoque en lógica escalable. Se priorizó una arquitectura que pudiera soportar ataques, estados y fases sin reescritura futura.

Objetivos Alcanzados
✓
Script base del enemigo desarrollado
✓
Comportamiento inicial programado
✓
Funcionamiento validado en escenario de prueba
✓
Base lista para ataques y estados futuros
Complicaciones

La dificultad no estuvo en hacer que el enemigo apareciera, sino en organizar su lógica de forma que el sistema pudiera crecer sin deuda técnica. Se tomaron decisiones de arquitectura que afectan a todo el pipeline de enemigos.

Próximos Pasos
Agregar acciones ofensivas al enemigo
Probar interacciones de combate reales
Refinar detección de colisiones y hitboxes

Complicaciones y Coherencia

El reto fue que cada ataque tuviera función clara dentro del combate, no solo ser técnicamente distintos. Se trabajó en dar a cada patrón una intención de diseño concreta.

El Verdugo ya estaba definido en la propuesta con ataques telegráficos y hacha. Esta semana alineó la programación con el diseño de personaje existente.
